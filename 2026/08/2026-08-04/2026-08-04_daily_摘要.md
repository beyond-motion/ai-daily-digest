## 1. 🤖 Steve Yegge 谈 Coding Agent 的脆弱性：Opus 4.7 让 Gas Town 付之一炬

**来源**: Simon Willison's Weblog · **作者**: Simon Willison  
**时间**: 2026-08-04 00:42  
**链接**: https://simonwillison.net/2026/Aug/4/steve-yegge/

Simon Willison 引用了 Steve Yegge 的最新文章《The Shape of Things to Come》，其中描述了一个令人警醒的现象：Yegge 构建的 coding agent 框架 "Gas Town" 在 Opus 4.6 时代运行良好，但 Opus 4.7 的发布彻底摧毁了它。

问题出在 Opus 4.7 引入了一个"just two more things"的行为模式——模型永远无法收敛到"准备开始真正工作"的状态，而是不断想对框架本身进行微调。这个"tic"（抽搐式行为）从未被修复，导致 Gas Town 从一个可复用工具退化成了只能建造自身的空转机器。

**启示**：LLM 的行为漂移是真实存在的。一个在特定模型版本上完美运行的 agent 系统，可能因为模型的细微行为变化而彻底失效。这对所有构建 coding agent 的人来说都是一个重要警告。

## 2. 🚫 "不要做肉身代理"——AI 时代的新警示语

**来源**: Simon Willison's Weblog · **作者**: Simon Willison  
**时间**: 2026-08-03 23:45  
**链接**: https://simonwillison.net/2026/Aug/3/dont-be-a-meat-proxy/

Niklas Gruhn 创造了一个精辟的新词——**"meat proxy"（肉身代理）**，专指那些盲目复制粘贴 AI 输出然后转发给同事的人。

Simon Willison 引用并深表赞同：你当然可以用 AI 辅助工作，但不要只是中继它的输出。**读它、理解它、验证它，然后用你自己的话写出回复**——这才是你能提供的真正价值。如果你只是无脑转发 AI 的回答，你就是在做一个昂贵的、不可靠的 API 网关。

## 4. 💰 Dwarkesh：更智能的 AI 模型可能让算力价格暴涨 10 倍

**来源**: Dwarkesh · **作者**: Dwarkesh Patel  
**时间**: 2026-08-03 17:32  
**链接**: https://www.dwarkesh.com/p/why-compute-might-get-10x-more-expensive-video

Dwarkesh Patel 探讨了一个反直觉的观点：随着 AI 模型变得更聪明，算力不仅不会变得更便宜，反而可能**暴涨 10 倍**。

核心逻辑在于推理时扩展（inference-time scaling）——更聪明的模型会被要求思考更长时间、解决更难的问题，每个 token 的经济价值也随之攀升。当模型从"回答简单问题"升级到"解决前沿研究问题"，对高质量算力的需求将呈指数级增长，推动价格上而非下降。

## 6. 🔐 Apple 用 iCloud 分享内部文件——一种反直觉的安全策略

**来源**: Daring Fireball · **作者**: John Gruber  
**时间**: 2026-08-03 21:45  
**链接**: https://www.theinformation.com/articles/apple-icloud-policy-fueled-employee-leaks-ahead-openai-suit

The Information 报道了一个令人意外的 Apple 内部政策：新员工入职时，Apple 会发放 iPhone 和 Mac，并鼓励他们用**个人 Apple ID** 绑定公司付费的大容量 iCloud 账户。同事通过这个 iCloud 账户分享内部文件。

这种做法有其便利性考量——iPhone 一次只能登录一个 Apple ID——但也意味着员工离职时，公司机密文件可能残留在个人 iCloud 中。这一政策在 OpenAI 诉讼前夕的泄露事件中成为了焦点。

## 7. 📡 MCP vs REST：连接 Agent 与 API 的正确方式

**来源**: Daring Fireball (赞助) · **作者**: WorkOS  
**时间**: 2026-08-03 22:26  
**链接**: https://workos.com/blog/mcp-vs-rest

WorkOS 发表了一篇关于 MCP（Model Context Protocol）与 REST 关系的深度文章。核心观点：**MCP 和 REST 不是竞争对手，而是不同层级的协议**。大多数 MCP server 内部实际上是在调用 REST API 完成实际工作。

好的 MCP server 不是把每个 endpoint 机械地转换成 tool，而是围绕 agent 的目标来设计。同时，部署 MCP server 意味着需要处理 OAuth 2.1 和 scoped tokens——这正是 WorkOS AuthKit 解决的问题。

## 9. 🔓 开发工具必须开源：LLM 改变了开源的经济学

**来源**: Simon Willison's Weblog · **作者**: Simon Willison  
**时间**: 2026-08-03 15:30  
**链接**: https://simonwillison.net/2026/Aug/3/devtools-must-be-open-source-exedev/

Simon Willison 在 Hacker News 评论中指出，LLM 已经从根本上改变了开源软件的价值方程。

过去，开源软件的"自由查看和修改"对大多数人来说只是理论权利——即使是专家程序员也很难 justify 花时间去读和修改工具代码。但 **LLM 让这个原始愿景变得切实可行**：现在他每天多次用 prompt 让 AI 读取开源工具代码、理解其行为、进行定制修改。

David Crawshaw 提出了一个精彩的 prompt 示例：设置一个 nightly cron job，自动 fetch 上游变更、rebase 本地修改、验证软件正常工作并替换当前版本。这是 agent 时代维护 fork 的新范式。
